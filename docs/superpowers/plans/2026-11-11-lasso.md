# Lasso Select, Move & Resize Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Lasso tool that selects board objects with a free loop, then moves them (centre button or inside the box), resizes them with a locked aspect ratio (corners) or stretches them one way (side-centres), with one undo step per drag.

**Architecture:**
- Pure maths lives in `src/tools/lasso.ts`: selection, bounds, handle hit-testing and transforms.
- A small gesture state machine lives in `src/tools/selectionController.ts`. It holds ids, never copies.
- `Renderer` gains a hidden-ids filter. `LiveLayer` draws the loop, the dragged preview and the box with its handles.
- `main.ts` only routes stroke actions to the controller when the tool is `'lasso'`.
- The router gains an optional `claimTouch` callback, so a finger on the selection drags it instead of panning.

**Tech Stack:** TypeScript (strict), Vite, Vitest + jsdom. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-11-lasso-design.md`. Decisions L1–L14 are in `docs/superpowers/decisions/sketchboard-decisions.md`.

- Selection rule: a **stroke, shape or arrow** qualifies when **≥ 60 %** of its points (strokes) or `outlineOf` points (shapes and arrows) lie inside the closed loop. Text qualifies when its **bbox centre** lies inside.
- Tiny loop: if the loop's bbox is **< 20 screen px in both** width and height, nothing is selected.
- Box padding is **8 screen px**. Handle hit areas are **44 screen px** squares, centred on the handle.
- Drawn handle sizes:
  - corners: **16 px** squares
  - sides: **14 px** squares
  - move button: **32 px** circle
- Side handles are hidden when the padded box is **< 88 px** in either direction.
- Hit priority: **corner > side > move > inside**.
- Scale clamp: **≥ 0.05**, and the selection never flips.
- Text `fontSize` is clamped to **4–2000** board px on a uniform scale.
- Uniform (corner) scaling scales `size` and `fontSize` with `s`. A one-way stretch leaves `size` and `fontSize` unchanged.
- Transformed objects keep `id`, `createdAt`, `pen` and `color`. Their `bbox` is recomputed with `bboxOf`.
- A drag commits **one** `history.apply({ remove: originals, add: transformed })`. A cancel commits nothing.
- The selection ends on:
  - a pen-down or tap outside the box (which does **not** start a new lasso),
  - a tool change,
  - an S Pen side-button switch,
  - undo or redo,
  - leaving the board,
  - the app going hidden.
- The palm rule is unchanged: while the pen is near, fingers are inert, handles included.

## Review Focus
1. **Ids that vanish while selected**, for example erased or undone. The selection drops the missing ids, and if none are left it ends instead of drawing an empty box. Pinned in Task 3.
2. **Zoom or pan while a selection is active.** The box and its handle hit areas follow the current view (screen box recomputed from world bounds and the viewport). Pinned in Task 2.
3. **Dragging a corner or side past its anchor.** The scale clamps at 0.05; it never flips or goes to zero. Pinned in Task 2.
4. **App hidden or `pointercancel` mid-drag.** The originals reappear unchanged and no undo step or save happens. Pinned in Task 3, wired in Task 6.
5. **A lasso around empty space, or a tiny loop.** Nothing is selected, no undo step is recorded, and the loop disappears. Pinned in Task 1 and Task 3.

### Task 2: Handles and transforms

**Files:**
- Modify: `src/tools/lasso.ts`
- Test: `tests/tools/lasso.transform.test.ts`

**Interfaces:**
- Consumes: `Viewport` and `toScreen` (src/core/viewport.ts), `bboxOf`, plus Task 1's types.
- Produces:
  - `export type Handle = 'nw' | 'n' | 'ne' | 'e' | 'se' | 's' | 'sw' | 'w' | 'move' | 'inside'`
  - `export const BOX_PAD = 8, HANDLE_HIT = 44, SIDES_MIN = 88, MIN_SCALE = 0.05`
  - `export function screenBox(b: BBox, vp: Viewport): BBox` — the world bbox converted to screen, padded by `BOX_PAD`
  - `export function handlePoints(box: BBox): Record<Exclude<Handle, 'inside'>, Pt2>` — the screen centre of each handle. `move` sits at the box centre.
  - `export function hitHandle(box: BBox, x: number, y: number): Handle | null` — screen coordinates, using the priority and 44 px areas from Global Constraints. Sides are skipped when the box is under `SIDES_MIN`.
  - `export type Transform = { ax: number; ay: number; sx: number; sy: number; dx: number; dy: number; uniform: boolean }`
  - `export function transformFor(h: Handle, start: BBox, from: Pt2, to: Pt2): Transform` — world units; `start` is the unpadded world bounds at drag start
  - `export function transformObject(o: BoardObject, t: Transform): BoardObject` — applies `p' = a + (p − a)·(sx, sy) + (dx, dy)`

- [ ] **Step 1: Write the failing tests**
  - `screenBox` at `vp {x: 100, y: 0, zoom: 2}` of world box `(110, 10)–(120, 20)` gives `(12, 12)–(48, 48)`.
  - `hitHandle`:
    - On a 200×200 box at `(0, 0)`: `(2, 2)` → `'nw'`, `(100, 1)` → `'n'`, `(100, 100)` → `'move'`, `(60, 140)` → `'inside'`, `(300, 300)` → `null`.
    - Overlap case: a point within 22 px of both a corner and a side centre returns the corner.
    - On an 80×200 box, `(0, 100)` returns `'inside'` or `null`, never `'w'` (sides hidden).
    - After changing the viewport, the hit points move with `screenBox` (Review Focus 2).
  - `transformFor`:
    - `'move'` from `(0, 0)` to `(30, -10)` gives `{sx: 1, sy: 1, dx: 30, dy: -10}`.
    - `'se'` on start `(0, 0)–(100, 50)`, dragged from `(100, 50)` to `(200, 100)`, gives `uniform: true`, `sx = sy = 2`, anchor `(0, 0)`.
    - The same `'se'` drag to `(-500, -500)` gives `sx = sy = 0.05` (Review Focus 3).
    - `'e'` dragged to `x = 150` gives `sx = 1.5`, `sy = 1`, `uniform: false`, anchor `x = 0`.
    - `'w'` dragged past the anchor gives `sx = 0.05`.
  - `transformObject`:
    - A stroke scales its points; `size × 2` on uniform; `size` unchanged on stretch; pressure unchanged.
    - An ellipse: the centre moves, `rx × sx`, `ry × sy`.
    - Rect vertices are transformed.
    - Arrow `from` and `to` are transformed.
    - Text `x, y` are transformed; `fontSize × s` on uniform, clamped to 2000 and to 4; unchanged on stretch.
    - All results keep `id` and `createdAt`, and their `bbox` equals `bboxOf` of the result.

### Task 3: Selection controller

**Files:**
- Create: `src/tools/selectionController.ts`
- Test: `tests/tools/selectionController.test.ts`

**Interfaces:**
- Consumes: Tasks 1 and 2; `BoardDoc`; `Change` (src/core/history.ts); `Viewport`.
- Produces:
  - `export class SelectionController` with:
    - `constructor(private doc: BoardDoc, private onCommit: (c: Change) => void)`
    - `get active(): boolean` — true when the selection has at least one surviving id
    - `get ids(): string[]` — only ids still present in the doc
    - `get hidden(): Set<string>` — non-empty only while dragging
    - `get preview(): BoardObject[]` — the transformed copies while dragging, else `[]`
    - `get loop(): Pt2[] | null` — the world loop while lassoing
    - `bounds(): BBox | null` — preview bounds while dragging, otherwise the bounds of the selection
    - `down(wx: number, wy: number, sx: number, sy: number, vp: Viewport): 'drag' | 'lasso' | 'ended'`
    - `move(wx: number, wy: number): void`
    - `up(vp: Viewport): void`
    - `cancel(): void` — aborts a drag or lasso, with no commit
    - `clear(): void` — ends the selection
    - `hits(sx: number, sy: number, vp: Viewport): boolean` — true when a screen point is on a handle or inside the box

- [ ] **Step 1: Write the failing tests** (use a real `BoardDoc` and History-free spies)
  - Lasso flow: `down` returns `'lasso'`; moves trace a loop around 2 strokes; `up` makes `ids` contain both; `onCommit` is not called.
  - A tiny or empty lasso leaves the controller inactive, with no commit (Review Focus 5).
  - Drag flow:
    - On an active selection, `down` at the box centre returns `'drag'`.
    - During the move, `hidden` contains the ids and `preview` holds the moved copies.
    - `up` calls `onCommit` once, with `remove` = the originals and `add` = the transformed objects with the same ids.
    - After `up`, `hidden` is empty and the selection is still active.
  - `cancel()` mid-drag: `hidden` is cleared, `preview` is `[]`, and there is no commit (Review Focus 4).
  - On an active selection, `down` outside the box returns `'ended'`, the controller becomes inactive, and no lasso starts.
  - If an id is removed from the doc while selected, `ids` drops it. If all are removed, `active` is false and `bounds()` is null (Review Focus 1).
  - `hits` is true on a corner and inside the box, false outside.
- [ ] **Step 2: Run** `npx vitest run tests/tools/selectionController.test.ts`. Expect a FAIL.
- [ ] **Step 3: Implement** the states `idle | lassoing | selected | dragging`. The drag keeps `startBounds`, `from`, `handle` and the original objects.
- [ ] **Step 4: Run** the command again. Expect a PASS.
- [ ] **Step 5: Commit** `feat: selection controller for lasso move and resize`.

### Task 6: Lasso tool wiring

**Files:**
- Modify:
  - `src/core/toolState.ts` (add `'lasso'` to `Tool`)
  - `src/ui/icons.ts` (`lasso` icon: a dashed loop)
  - `src/ui/toolbar.ts` (Lasso button after Text)
  - `src/ui/toolBadge.ts` (label "Lasso")
  - `src/main.ts`
- Test: `tests/ui/toolbar.test.ts`, `tests/core/toolState.test.ts`

**Interfaces:**
- Consumes: everything above.
- Wiring in `main.ts`:
  1. Create `sel = new SelectionController(doc, (c) => history.apply(c))` per board, alongside `doc` and `history`.
  2. In `applyActions`, when `toolState.tool === 'lasso'`:
     - `strokeStart` → `sel.down`
     - `strokeMove` → `sel.move`
     - `strokeEnd` → `sel.up`
     - `strokeCancel` → `sel.cancel`

     After each of these, sync the view with `renderer.setHidden(sel.hidden)` and `live.drawSelection({ loop: sel.loop, preview: sel.preview, box: … })`, where the box is `sel.bounds()` mapped through `screenBox(…, vp)`. Snapping, the erasers and shapes never run for the lasso.
  3. Pass `claimTouch: (x, y) => toolState.tool === 'lasso' && sel.hits(x, y, vp)` to the router.
  4. Call `sel.clear()` (and redraw) in all of these:
     - `setTool` when the tool changes,
     - `undoRedo`,
     - `leaveBoard`,
     - the hidden handler (`sel.cancel()` first),
     - `resetSessions`.
  5. On pan or zoom while a selection is active, redraw the selection overlay at the new view.
  6. `sessionActive()` is true while `sel` is lassoing or dragging, so undo is disabled mid-gesture.
